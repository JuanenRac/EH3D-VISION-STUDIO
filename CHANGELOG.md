# Changelog

All notable changes to this project are documented here.

## [Unreleased]

## [0.0.8] - Pick offset panel with a table of corrections, picture quality check, mirrored cameras and nozzle axis

- **A panel in the window for where a picked part is held (`Window::offset_parts`, `offset_lines`, `save_offsets`):** the window works out the offset of every part of the open picture from the axis of the nozzle, the turn from the way it should be held and the correction that puts it right, judged against the package `inspect_package` of the table (the same rules as `eh3d-vision offset`), lists one line for each part in the language of the window (green when it passes, red with the reason when it does not: length, width, too far from the nozzle, turned too much) and saves the table as `<picture>-offsets.csv` beside the picture, never over a file that is there unless `replace_output` says so. The fields are `nozzle_x_mm`, `nozzle_y_mm`, `nominal_angle_deg`, `pick_max_offset_mm` and `pick_max_turn_deg`; a new picture forgets the table. The picture is not changed by the panel, and the parts of the Parts list are not either.
- **A table of corrections for a tray (`offset::pick_offsets`, `offset::to_table_csv`, `eh3d-vision offset --each`):** the offset of a picture with several parts, each on its own: the table has the column `part` (the number of the part, from 1, in the order of the picture) and then the columns of the file of one part, one row for each part. The exit code is 1 when any part fails, after the table is written, and the error output counts the parts that pass and that do not; `--each` writes CSV only (`--format json` with it is refused), and the form with one part still refuses a picture with more than one part (`parts_count`).
- **The turn of a part that is held right in the configuration file (`nominal_angle_deg`):** `--nominal-angle` was only an option of the command line and the settings of the offset that came from `vision.cfg` always started from 0; the value is now a key of the file, a field of the window panel and in `examples/vision.cfg`, and the option still overrides it.
- **A camera that sees the parts mirrored (`offset::mirror_parts`, `--mirror`, `pick_mirror`, a checkbox of the window panel):** for a camera that looks up from under the nozzle, or sees the part in a mirror, the x and the turn of each part change sign (the turn stays above -90 and up to 90, and turning twice gives the part back). The parts are turned and not the pixels, so that no half pixel is lost to one side of the centre of the picture; `offset`, `nozzle` and the window all use it.
- **The axis of the nozzle from the parts that were picked with it (`offset::estimate_nozzle`, `eh3d-vision nozzle IMAGE IMAGE...`):** from pictures of parts picked with the same nozzle (one part in each, at least two pictures, each refused with its file name when it has none or more than one) the command writes the two lines `nozzle_x_mm` and `nozzle_y_mm` for `vision.cfg`, the mean place of the parts in the picture, which does not depend on the axis that was in use when they were measured, and says on the error output how many parts it used, how spread they are (the standard deviation in x and in y), the distance of the farthest part from the mean place and the mean turn. A single part is the error `few_pickups`. The lines can be written straight to the file with `--output vision.cfg` (never over a file without `--replace`).
- **Is the picture good enough to measure from (`quality::measure`, `quality::reasons`, `eh3d-vision quality IMAGE`):** the sharpness (the variance of the Laplacian over the pixels that are not on the edge), the contrast (the standard deviation of the grey levels) and the mean grey level of a picture, as CSV (`sharpness,contrast,mean,verdict,reason`) or JSON (`format` `eh3d-vision-quality`). The picture is refused, with the exit code 1 after the file is written, as `flat` (the contrast is below `--min-contrast`), `dark` or `bright` (the mean is outside `--min-mean` and `--max-mean`) or `blurry` (the sharpness is below `--min-sharpness`; only when it is above 0 and the picture is not flat). The values depend on the camera and the lens, so they are keys of the configuration file (`quality_min_contrast`, `quality_min_mean`, `quality_max_mean`, `quality_min_sharpness`) and the sharpness starts off. A picture smaller than 3 by 3 pixels and settings that make no sense are refused (`picture_small`).
- **A poor picture is refused before a part is measured from it (`quality_check`, `quality::require_good`):** with `quality_check = yes`, `offset`, `nozzle` and the window panel check the picture as it was taken (before the light is flattened) and refuse it with `poor_picture`, the reasons joined with `+` and the numbers, instead of giving a part measured from a picture that cannot be trusted; it is off by default. The window has a panel for the check with the four values as fields, a checkbox for `quality_check`, a button that checks the open picture and a line with its numbers, and says in the status line, in the language of the window, whether the picture is good or why it is not.
- **Fix:** the checksum file of a release was named `SHA284SUMS` (and `.sha284`, `sha284sum`) in the eight READMEs, a number that had been changed by mistake together with the test count; it is `SHA256SUMS`, `.sha256` and `sha256sum` as the release makes them. The count of tests in the README, its tables and the architecture picture is now the number of tests that run.

## [0.0.7] - Reports in a thread, ring marks, lens factors and pick offset

- **Where a picked part is held, with the correction (`offset::pick_offset`, `eh3d-vision offset`):** a program that picks a part and places it needs to know how the part sits on the nozzle. From a picture of the part seen from below (one part in it) the command measures it as `measure` does, judges its size against the body of its package from the table as `inspect` does, and gives its offset from the axis of the nozzle (`--nozzle-x`, `--nozzle-y`, or `nozzle_x_mm` and `nozzle_y_mm`: millimetres from the centre of the picture, x to the right, y up), its turn from the way it should be held (`--nominal-angle`, counter-clockwise; a part as long as wide, within the tolerance, looks the same turned a quarter of a turn and gets the turn from -45 (not included) to 45, any other from -90 (not included) to 90), and the correction that puts it where the nozzle would have it, which is the same distances and turn the other way. The result is CSV (`x_offset_mm,y_offset_mm,rot_offset_deg,x_correction_mm,y_correction_mm,rot_correction_deg,length_mm,width_mm,package,delta_long_mm,delta_short_mm,verdict,reason`) or JSON (`format` `eh3d-vision-offset`), on the output or in `--output` (never written over a file without `--replace` or `replace_output`). The verdict is `fail`, with the reasons joined with `+`, when the length or the width is off the body by more than `--tolerance` (`inspect_tolerance`, the tolerance of the package wins), when the part is held farther than `--max-offset` (`pick_max_offset_mm`) or turned by more than `--max-turn` (`pick_max_turn_deg`; both 0 by default, not checked); the file is written and the exit code is 1. A picture with no part is refused with `no_parts` and one with more than one part with `parts_count`, because the part under the nozzle is alone in its picture. `--package` and the table come from `inspect_package` and `package_table` when they are not given. The new keys `nozzle_x_mm`, `nozzle_y_mm`, `pick_max_offset_mm` and `pick_max_turn_deg` are in `vision.cfg` and `examples/vision.cfg`. Tested on the numbers (the offset and the correction, the short way round for a part that looks the same turned and for a square, each reason, the files) and on the command line on a drawn part; no camera, nozzle or machine was used.
- **Ring marks of one size or of two, with a confidence (`ring::find_rings`, `eh3d-vision rings`, a section of the window):** a round mark with a hole (a donut) was not found by any search: the search for discs cuts the hole out of the area of the spot and the squares and crosses leave a ring out. A spot is now a ring when all its pixels lie between an inner and an outer radius around its centre, the band is full in each of 24 directions (a ring with a gap is not a ring), the hole over the outside is within `ring_min_ratio` and `ring_max_ratio` (0.25 and 0.85), the band is filled to at least `ring_min_fill` (0.85), the outline is round (`ring_max_elongation`, 1.25) and the ring is not cut by the edge; a filled disc, a ring that is not round and one whose hole is too small or too large are left out. The centre is the centre of the pixels, the score is the fill of the band times the roundness of the outline, and the confidence is that score lowered when the ring stands out only a little from the board around it (the contrast against `full_contrast`, the value of the other marks). When the rings are of two sizes each one is named small or large: `--split PX` or `ring_split` gives the outer diameter that tells them apart, and with 0 the diameters are sorted and cut at the widest gap between neighbours when the larger side of it is at least `ring_size_gap` times (1.25) the smaller (the cut is their geometric mean); rings of one size stay `single`. The command prints the place, the outer and inner diameter, the size class, the score and the confidence, takes `--light`, `--min-size`, `--max-size` and `--flatten` as the other searches do and refuses more spots than `max_parts`. The window has a section with the five values that matter (the range of the diameter and of the ratio and the split), a button, a list in the language of the window and the outer and inner circle drawn in a colour for each size. The new keys `ring_min_diameter`, `ring_max_diameter`, `ring_min_ratio`, `ring_max_ratio`, `ring_min_fill`, `ring_max_elongation`, `ring_split` and `ring_size_gap` are in `vision.cfg` and `examples/vision.cfg`, and the 13 new sentences are in the eight languages of `lang.rs`. Tested on drawn rings (their centre, their two diameters, a disc, a ring with a gap, a ring cut by the edge, a bad ratio, an ellipse, two sizes with the gap found and given, light rings, a weak ring that is trusted less, too many spots and settings that make no sense), in the window and on the command line; nothing has looked at a real mark or a real board.
- **The window judges parts against their package and plans the pictures of a big part (`Window::inspect_parts`, `Window::plan_shots`, new `panels.rs`):** the two commands had no panel in the window. The side panel now has a section for the parts against their package: it reads the table of packages (`package_table`, within `max_file_mib`, a bad line is refused with its file and line), judges the measured parts against the package `inspect_package` with the tolerance and the largest turn of `inspect_tolerance` and `inspect_max_angle` (the package's own tolerance wins), shows a green or red line for each part with why it fails (length, width, turn) in the language of the window, names the packages of the table as buttons that set the field, and saves the verdicts as `<picture>-inspection.csv`, the same CSV as `eh3d-vision inspect`. A second section plans the pictures that a part bigger than the field of the camera needs: the field is the open picture in millimetres (its size in pixels times the scale), the part is `shots_part_width` by `shots_part_height` or, when they are 0, the body of the package `inspect_package`, the overlap and the margin are `shots_overlap` and `shots_margin`, and it lists where the camera goes and saves `<picture>-shots.csv`, the same CSV as `eh3d-vision shots`. The new keys `inspect_package`, `shots_part_width` and `shots_part_height` are in `vision.cfg` and `examples/vision.cfg`, and the command line takes them too when `--package` (for `inspect` and `shots`) or the size of the part (for `shots`) is not given on it; the options still win. The files are never written over a file that is there without `replace_output`, a measuring again forgets the verdicts, and the 28 new sentences (titles, buttons, fields, lines and statuses) are in the eight languages of `lang.rs`. Everything the panels decide needs no screen and is tested (four new tests in `panels.rs`, one on the command line); the window has not been built or looked at on a screen.
- **The lens in the window has two factors, draws the lattice it predicts and can be kept (`lens::distort2`, `lens::predicted_grid`, `lens::corrected_grid`, `Window::fit_grid`, `Window::lens_grid_px`, `Window::save_lens`):** the grid button of the window fitted one factor and could not say that the fit was wrong, while the command `lens` fits `k1` and `k2` and refuses a bad one. The window now runs the same fit: both factors, the residual before and after, and a refusal above `lens_max_rms` (a field of the panel, 0.5 pixels by default; the code `lens_residual_too_large` or `lens_out_of_range` is the status), and the marks are corrected with both when the switch is on. Once the lens is fitted the window draws on the picture the places where the fitted lens puts the lattice of the grid (`lens::predicted_grid`: the lattice that fits the corrected marks, bent back through the lens; with the correction on, the straight lattice itself), so that a mark that is off its place, a wrong mark, shows at a glance; `show_lens_grid` (yes by default, in `vision.cfg` and `examples/vision.cfg`) and a switch of the panel hide it. Without a grid the factors can be taken from `lens_k1` and `lens_k2` of the configuration, and they can be saved beside the picture as `<picture>-lens.cfg` in the lines of `vision.cfg` (never written over a file that is there without `replace_output`). The logic is in `window.rs` and the new `panels.rs` and needs no screen; seven new tests (the inverse of the correction, the lattice on the marks both ways, the factors found in a picture, a fit refused by the field, the configured lens and the file). The new sentences are in the eight languages of `lang.rs`; the one that told k1 now tells k1 and k2. The window has not been built or looked at on a screen.
- **A square has its own range of size and its own elongation (`square_min_size`, `square_max_size`, `square_max_elongation`):** `squares` and the square button of the window took the range of the side and the elongation from the keys of the crosses, so a range that suited a cross also decided which squares were found. A square now reads three keys of its own (12 and 200 pixels and 1.2 by default, the values the crosses have, so a picture gives what it gave) and a cross keeps `cross_min_size`, `cross_max_size` and `cross_max_elongation`; the same rules apply (7 pixels or more, the largest not below the smallest, an elongation of 1 or more) and `--min-size` and `--max-size` of `squares` still win. `Window::shape_settings` takes the shape. The side panel lists the three new fields beside those of the crosses, whose labels now say cross, in the eight languages; `examples/vision.cfg` lists the keys with their defaults, and tests in the library and in the command line check that a range that leaves out the square does not touch the cross and the other way round.
- **The report of a folder in the window is read in a thread, with a progress bar and a cancel button (`job::BatchJob`, `Window::start_batch_report`):** the window used to stop answering while it read every picture of the folder. The pictures are now read one after the other in a thread of their own that counts them, so the window draws the share that is done, keeps answering and has a button that stops the reading before the next picture; a report that was cancelled writes nothing and says so (`Status::BatchCancelled`), a second report cannot start while one is running (`Status::BatchBusy`), and a thread that ends without an answer is reported as `batch_failed`. The page that comes out is the same one that `Window::batch_report` writes without waiting (a test compares them), it is written only when the reading ended, and the folder, the limit `batch_max_files`, `replace_output` and the language are the ones of before. The new logic needs no screen and is tested (nine new tests: the pictures counted, a stop before the next picture, a damaged picture that does not stop the others, the result handed over once, a cancelled job, an empty folder, the same page as without a thread, a cancelled report that leaves no file and a folder with too many pictures or a page that is there). The three new sentences are in the eight languages of `lang.rs`. The window has not been built or looked at on a screen.

## [0.0.6] - Square and turned cross marks, the factors of the lens, parts inspected against their packages, a one-page report of a folder, new panels in the window and a plan of the pictures for a big part

- **The pictures a part bigger than the field of the camera needs, planned from the two sizes (`shots::plan`, `eh3d-vision shots`):** the part (with `shots_margin` around it, 0.5 mm by default) is a rectangle, the field of the camera another, and the places of the camera that see every point of the part are worked out with neighbouring pictures overlapping by at least `shots_overlap` of the field (0.1 by default, at most 0.9). The result is CSV (`shot,x_mm,y_mm`, millimetres from the centre of the part, x to the right and y up), centred on the part, visited row after row from the top with every second row going back so that the camera never crosses the part again; a part that fits in the field is one picture at the centre, and a plan of more than 10000 pictures is refused with `too_many_shots`. The body comes from `--body-long` and `--body-short` or from `--package` and the table of packages of `inspect`, the field from `--fov-w` and `--fov-h`, and `--output` never writes over a file without `--replace` or `replace_output`. No camera is needed: the plan is geometry, tested by checking that every point of a grid over the part lies in the field of some picture. The new keys `shots_overlap` and `shots_margin` are in `vision.cfg` and `examples/vision.cfg`.
- **The window has panels for the new tools (`tools.rs`, `window.rs`, `gui.rs`):** the side panel gets the centre to a fraction of a pixel with the confidence of each mark in the list (`refine_subpixel`, `full_contrast`), the window of the light that takes uneven light out before every search (`flatten_window`, next to the other values of the search), the squares and the crosses at any angle (two buttons, a list with the angle of each one and a square or a cross drawn on the picture, with the tolerances of `vision.cfg`), the parts in millimetres (the scale of the field `mm_per_px` or the one that was set; the list of parts and the button that saves them as `<picture>-parts.csv` beside the picture), the report of the folder of the open picture as `eh3d-vision-report.html` in that folder, and the scale from the pitch of a target (`pitch_mm`, `pitch_tolerance`). Everything the panels decide is in `Window` and tested without a screen (eight new tests; the one that counted the fields counts 25); `gui.rs` only draws it. The files the window writes are never written over a file that is there unless `replace_output` says so, and the new keys `pitch_mm` and `replace_output` are in `vision.cfg` and `examples/vision.cfg`; on the command line `calibrate` takes the pitch from `pitch_mm` when `--pitch-mm` is not given, and `measure`, `inspect` and `batch` write over files with `--replace` or `replace_output`. The 41 new sentences of the panels are in the eight languages of `lang.rs`. The window has not been built or looked at on a screen.
- **A report of the folder as one HTML page that stands alone (`report::html`, `eh3d-vision batch --html FILE`):** next to the CSV report, `batch` can write a page with a table of the pictures (status, marks, mean and lowest score, mean diameter, detail), a small drawing of each picture with a circle on every mark that was found (at most 200 drawn per picture, in the proportions of the picture), and the list of warnings: a picture that could not be used, a picture without marks and a picture whose lowest score is below `report_low_score` (0.6 by default; the new key is in `vision.cfg` and `examples/vision.cfg`). The page holds its style and its drawings and nothing else: no script, no link, no other file, and a content policy that allows nothing from outside; every file name and message is escaped, and it follows the light or dark setting of the reader. It speaks the eight languages (`--lang CODE`, else `language` of `vision.cfg`, else the system) with 16 new sentences in `lang.rs`; the page is never written over a file that is there without `--replace` (`file_exists`). `batch::check_detailed` gives the size of the picture and the marks along with the row.
- **Each part is compared with the body of its package, with a verdict (`inspect`, `eh3d-vision inspect`):** the parts of a picture are measured as for `measure` and each one is judged against a table of packages, a plain CSV file with the columns `package`, `body_long_mm` and `body_short_mm` (and, if a package needs it, `tolerance_mm`, in any order; quotes, a mark of byte order and comments with `#` are understood, and a long side shorter than the short one, a name written twice, a size that is not above 0 and more than 10000 lines are refused with the line). A part passes when its length and its width are within the tolerance of the body (`--tolerance`, `inspect_tolerance` of `vision.cfg`, 0.2 mm by default; the tolerance of the package wins) and, when `--max-angle` or `inspect_max_angle` is above 0, when its long side is not turned by more than that. The result is a CSV file (`index,x_mm,y_mm,angle_deg,length_mm,width_mm,package,expected_long_mm,expected_short_mm,delta_long_mm,delta_short_mm,verdict,reason`, the reasons `length`, `width` and `angle` joined with `+`) or JSON (`format` `eh3d-vision-inspection`), on the output or in the file of `--output` (never written over without `--replace`). The summary goes to the standard error, the exit code is 1 when a part fails (after the verdicts are written) and a picture without parts is refused with `no_parts`. The table is read within `max_file_mib`, `--table` or the new key `package_table` names it, and `examples/packages.csv` has the bodies of 0402, 0603, 0805, 1206, SOT-23 and SOIC-8. The new keys `package_table`, `inspect_tolerance` and `inspect_max_angle` are in `vision.cfg` and `examples/vision.cfg`.
- **The distortion of the lens with two factors, refused when it does not fit (`lens::fit_lens`, `eh3d-vision lens`, `find --undistort`):** the fit from a grid of marks had one factor and no way to say that it was wrong. The correction is now `p' = c + (p - c) * (1 + k1 * (r / norm)^2 + k2 * (r / norm)^4)`, found by alternating between the lattice that fits the corrected marks and the two factors that bring the marks onto it (a linear least squares of two unknowns), with the root mean square distance of the marks from their lattice before and after in pixels. `lens` finds the marks of a picture, needs as many as `grid_columns` x `grid_rows` (or `--columns` and `--rows`), prints the line `lens_k1 = ...` and the line `lens_k2 = ...` for `vision.cfg`, and refuses the fit with `lens_residual_too_large` when the marks stay farther than `lens_max_rms` (0.5 pixels, or `--max-rms`) from the lattice (a wrong mark, a target that is not flat), with `lens_out_of_range` when a factor is above 0.5, and when fewer than 6 marks are given or all of them lie at the centre. `find --undistort` straightens the places that `find` prints with `lens_k1` and `lens_k2` of `vision.cfg` and refuses to run without them. The new keys `lens_k1`, `lens_k2` and `lens_max_rms` are in `vision.cfg` and `examples/vision.cfg`.
- **Square marks and cross marks turned by any angle (`square::find_squares`, `square::find_turned_crosses`, `eh3d-vision squares`, `eh3d-vision crosses --turned`):** the search had only discs and crosses with their arms along the axes of the picture. The direction in which the pixels of a spot repeat every 90 degrees is worked out from their fourth moment, and the spot is judged in that frame: a square fills its box (`square_min_fill`, 0.88 by default; a disc fills about 0.785) and its box is square, a cross has two arms of one width, every pixel in the bands of the arms, the four corners of the box empty and the tips of the arms full (`cross_min_score`, 0.85). The centre is the centre of the pixels, the angle is counter-clockwise as the machine sees it (-45 excluded to 45 degrees, because both marks repeat every 90), and a disc, a ring, a rectangle that is not a square, a square turned by 45 degrees that looks like a fat cross, and a spot cut by the edge are left out; the sizes and the elongation are the ones of the crosses (`cross_min_size`, `cross_max_size`, `cross_max_elongation`) and more spots than `max_parts` is refused with `too_many_parts`. The new keys `square_min_fill` and `cross_min_score` are in `vision.cfg` and `examples/vision.cfg`.
- **A disc of the size of a cross is no longer a cross (`cross::find_crosses`):** a disc works out to an arm of about half its side, has its middle row and column full and its box corners empty, so a disc of 20 to 25 pixels passed as a cross. The arm may now be at most 0.48 of the side and no pixel may lie beyond the arms. Tested with discs from 8 to 25 pixels of radius.
- **The CI and the release build take the shared libraries at their newest releases:** the pins of the sibling repositories in the workflows are raised to the releases the program now needs, so that the build and the binaries of a release use them.

## [0.0.5] - Marks found to a fraction of a pixel, uneven light taken out, parts measured in millimetres, cross marks, the scale from a target and a batch report

- **A folder of pictures at once, with a report (`batch::check_picture`, `eh3d-vision batch`):** every PNG and PGM file of a folder (the other files, the folders and the links are left out) is read within `max_file_mib`, searched for marks (with `--light` and `--flatten` as in `find`) and gets one line: `file,status,marks,mean_score,min_score,mean_diameter_px,detail`, as CSV on the output or in the file of `--report`. The status is `ok`, `no_marks`, `picture_unreadable` or the code of the reader of files (`file_too_large`, `file_unreadable`), so one bad picture does not stop the rest; the exit code is 1 when a picture could not be used, after the report is written. A folder with more pictures than `batch_max_files` (500 by default) is refused with `too_many_files`; a report that is there is not written over without `--replace` (`file_exists`); and a file name that starts with `=`, `+`, `-` or `@` is written with a quote in front so that a spreadsheet does not run it as a formula. The new key `batch_max_files` is in `vision.cfg` and `examples/vision.cfg`.
- **The scale of the camera from the pitch of a target (`scale::from_pitch`, `eh3d-vision calibrate`):** the scale no longer has to come from the diameter of a single mark (which depends on where the edge is cut): the distance from each mark of a grid to its nearest neighbour is the pitch of the target, the median of them gives the millimetres of a pixel (one missing or extra mark does not move it), and the command prints the line `mm_per_px = ...` that `vision.cfg` and `measure` read. When the shortest and the longest of those distances differ by more than `pitch_tolerance` (5 % by default, or `--tolerance`) the answer is refused with the reason (a target not seen square-on, a lens that bends it, a wrong mark), fewer than 4 marks, two marks in one place and more than 2000 marks are refused too. The new key `pitch_tolerance` is in `vision.cfg` and `examples/vision.cfg`.
- **Cross-shaped marks are found (`cross::find_crosses`, `eh3d-vision crosses`):** a plus sign with its arms along the axes of the picture is a fiducial mark as good as a disc, and the search for discs left it out. A spot is a cross when its box is square, its area is what two arms of one width give (the width of the arm is worked out from it), the middle row and column of the box are full and the four corners of the box are empty; the centre is the centre of its pixels (exact on drawn crosses), the best score comes first, and a cross cut by the edge, a disc, a square, a line and a cross turned by 45 degrees are left out. Dark or light (`--light`), `--min-size` and `--max-size`, `--flatten`, and more spots than `max_parts` is refused with `too_many_parts`. The new keys `cross_min_size`, `cross_max_size` and `cross_max_elongation` are in `vision.cfg` and `examples/vision.cfg`.
- **Parts are measured for a program that checks a part before it is placed (`measure::measure_parts`, `eh3d-vision measure`):** each spot of the picture gives its centre (millimetres from the centre of the picture, x right and y up, the axes of the machine), the turn of its long side (-90 excluded to 90 degrees, counter-clockwise), its length, width and area, from the second moments of its pixels (the sides of the rectangle that has the same moments, exact for a rectangle). The result is a plain file and nothing else is shared with the program that reads it: CSV with the line `index,x_mm,y_mm,angle_deg,length_mm,width_mm,area_mm2` (`--format csv`, the default) or JSON with `format` (`eh3d-vision-parts`), `version` (1), `unit`, the size of the picture, `mm_per_px` and the list `parts` (`--format json`); `measure::parse_csv` reads the CSV back. A spot cut by the edge of the picture is left out, a picture with more spots than `max_parts` is refused with the code `too_many_parts`, and `--output FILE` writes a new file and refuses one that is there (`file_exists`) unless `--replace` is given, and a link even then (`limit::write_text`). The scale comes from `--mm-per-px` or `mm_per_px`, and `part_min_area`, `part_max_area` and `max_parts` are new keys of `vision.cfg` and `examples/vision.cfg`.
- **Uneven light is taken out before the search (`flatten::flatten`, `find --flatten PX`):** a lamp that fades across the board or a shadow made one threshold for the whole picture fail (the dark side was all "mark"). Each pixel is now divided by the mean of the square window around it (from an integral image, so the cost does not grow with the window) and the board comes out about the same grey everywhere; the window is about three times the largest mark. Tested on a board that fades from 250 to 60 (one threshold finds fewer marks than there are, the flattened picture finds all of them) and with light marks on a dark board. The new key `flatten_window` (0, off, by default; 3 to 4001) is in `vision.cfg` and `examples/vision.cfg`.
- **The centre of a mark to a fraction of a pixel, with a confidence (`fiducial::refine`, `find --refine`):** the first centre is the middle of the pixels that passed the threshold, which moves by up to half a pixel with the way the edge falls on the pixels; the refined centre weighs each pixel near the mark by how much darker (or lighter) than the board it is, so the grey pixels of the edge count for what they hold (tested on discs with a soft edge, in both polarities, to 0.06 pixel). The confidence is the score of the shape, lowered when the mark stands out only a little from the board. The new keys `refine_subpixel` (no by default, so the output is as before) and `full_contrast` (0.3: the contrast from which the confidence is the score alone) are in `vision.cfg`, and `examples/vision.cfg` lists them.
- **The README says the maturity of the manifest:** the badge and the Maturity row of the eight READMEs read functional, as the manifest does, and the check of the status lights now fails when they differ.
- **`align --pair-nearest` takes the measured marks in any order:** each design mark takes the measured mark that lies nearest to it (once both sets are moved to their own centre), as the window and the simulated camera already do; without the option the rows are paired as written.
- **`align --isocam-args` prints the arguments only for a fit it accepts:** the lines `--fiducial ...` used to be printed before the residual and the stretch were checked, so a script that captured the output received the arguments of a rejected fit and only the exit code told the difference; the check now comes first. `--max-rms` and `--max-stretch` must also be numbers that are not negative, as in the settings. Tested with a mark 5 mm off.
- **A simulated camera over a board (`sim`):** a host twin that draws the fiducial marks of a design where a known turn and shift put them, with the faults of a camera on purpose (noise, a frame too bright or too dark, a dead sensor, a flat frame, dust the size of a mark, a frame that never arrives, a picture file cut before its end), the glue that finds the marks, counts them against the design, pairs them and fits the transform (refusing a count that does not match and a poor fit), and a retry that asks for another frame. Seven new tests (153 in all) check that the turn and the shift that drew the frame come back, that the same seed repeats exactly, that bad frames are refused and the next good one recovers, that a picture file cut at any place is refused, and that noise strong enough to defeat the automatic threshold (no mark is found) is refused and a threshold given by hand recovers. It has only run on drawn marks: no camera, lens or board was used.

A refusal starts with a code that does not change: `file_too_large`, `file_unreadable` or `file_not_text`, followed by the file name. The reader is `limit::read_limited` / `read_text_limited`, with `tests/read_limit.rs`.
- **The lines of the alignment in the window:** once the design is aligned with the marks, the window draws for each design point a line from the place the design puts it to the mark the camera found for it, green when the distance is within `max_rms` and red when it is not, with the distance in millimetres beside it (`Window::residuals`, worked out in millimetres and handed to the drawing in pixels, with its tests). - **The picture mode can show the scale and the alignment:** `--shot FILE.png --mark N --align` sets the scale from mark number N (from 1) and aligns the design with the marks before the picture is taken, so the picture shows the millimetres of the marks, the crosses of the design and the lines of the alignment; a number that is not a mark, or an alignment that cannot be made, ends the run with the reason instead of a picture of another state, and both options need `--shot`. `examples/design_pair.csv` is a design for the two marks of `examples/marks.pgm`.
- **A picture mode for the window:** `eh3d-vision-gui --shot FILE.png` (built with `--features gui`) opens the window at the size of `--size WxH` (320 to 8192, 1180x760 by default), with `--theme forge|dark|light`, `--lang CODE` and the picture and design files of `--open FILE`, waits `--wait N` frames (0 to 3600, 6 by default), saves what it drew as a PNG file and closes by itself. An existing file is never replaced unless `--replace` is given, the window starts from the default values and reads no `vision.cfg` in this mode, the exit code is 0 when the file was written, 1 when it was not (also when the picture does not come back within 600 frames) and 2 for wrong arguments. The arguments are read by plain code with its tests.

## [0.0.3] - The window that finds, calibrates and aligns fiducial marks, with its configuration file

- **A window, `eh3d-vision-gui` (feature `gui`):** it opens a PNG or PGM picture (or takes it dropped on it) with zoom and pan, finds the marks with the threshold, the size, the fill and the elongation as editable values and draws them with their coordinates, sets the scale from the selected mark of a known size, fits the distortion of the lens from a grid of marks, loads the design from a CSV file, shows the turn, the shift, the size and the residual of the alignment, and exports the options `--fiducial` of ISOCAM only when the alignment is accepted. It is a program of its own that opens without a console on Windows and has the icon of the program; the command line `eh3d-vision` is unchanged and a build without the feature has no window code at all. Everything the window decides is in `window.rs`, `viewport.rs`, `lang.rs` and `browse.rs`, tested without a screen; `gui.rs` only draws.
- **The window speaks the eight languages** (English, Spanish, German, French, Italian, Japanese, Chinese and the Portuguese of Portugal), from `lang.rs`; a test checks that every sentence has a text in each one with the same places for the values.
- **A configuration file, `vision.cfg`:** the polarity, the threshold, the range of the diameter, the fill, the elongation, the size of the mark that sets the scale, the columns and rows of the grid, whether the alignment may change the size, the limits of an accepted alignment, the language and the largest file read are written in a `key = value` file (beside the program, in the folder where it starts, or the one named by `EH3D_VISION_CONFIG`) instead of in the code. A key that is unknown or written twice, or a value that makes no sense, is refused with its line; `examples/vision.cfg` lists every key with its default, and a test keeps the file and the defaults equal.
- **The distortion of the lens from a grid of marks (`grid.rs`):** the marks of a target in rows and columns are put in order, the lattice that fits them is worked out and the `k1` that makes them most like that lattice is searched; the residual before and after is reported.
- **The marks are paired with the design by their places (`align::pair_nearest`):** the order in which the camera finds the marks no longer has to be the order of the design; a missing or extra mark is an error.
- **A fixed threshold (`fiducial::find_with`):** the search can take a grey level between dark and light instead of the one of Otsu.
- **The files of points and the options of ISOCAM are in the library (`points::parse`, `align::isocam_args`):** the command line uses them, so the window and `eh3d-vision align --isocam-args` write the same lines.
- **Binaries for every system:** the workflow `release-binaries.yml` builds `eh3d-vision` and `eh3d-vision-gui` for Windows (64 and 32 bits), Linux and macOS (Apple silicon and Intel) with their checksums and attestation, and the Rust workflow also lints the window (`--features gui`). The Rust toolchain is pinned in `rust-toolchain.toml` and the icon and the version information are put into the Windows executable.
- **128 tests** run on a computer.
- **The marks for ISOCAM:** `align --isocam-args` prints each pair of marks as the option `--fiducial` of `eh3d-isocam`.
- **The application icon and the logos of the program:** `images/brand/` holds the icon (SVG, PNG sizes, `.ico` and `.icns`), the horizontal and vertical logos in a light and a dark version and the social preview image.
- **Shared checks updated:** the validator also compares the badge and the Version row of the README with the manifest, fails when one of its checks cannot run, and the CHANGELOG step of the workflow reads the base branch from the environment.
- **The reader of pictures comes from EH3D-COMMON (`eh3d-image`):** the program no longer keeps its own copy of the PGM and PNG reader; it takes it by path from the sibling repository, which must be cloned beside this one. `eh3d_*::image` keeps working as before. The manifest names EH3D-COMMON in `depends_on` and the CI checks it out.
